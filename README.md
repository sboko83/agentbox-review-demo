# agentbox

Веб-платформа для запуска агентов: чат с выполнением кода, настраиваемые
политики входа и выхода, судья, прогоны одного запроса на множестве
конфигураций. Параметры настроек взяты из заданий недели 1.

Решения — [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md), история изменений —
[CHANGELOG.md](CHANGELOG.md).

## Установка

```bash
python3 -m venv backend/.venv
backend/.venv/bin/pip install -e 'backend[dev]'
npm --prefix frontend install
```

Нужен файл `../secrets/.env` с ключом `OPENCODE_API_KEY=sk-...`. Базовый URL
Zen можно переопределить через `OPENCODE_BASE_URL` (шаблон —
`../secrets/.env.example`).

## Запуск

```bash
./dev.sh
```

Бэкенд на `http://127.0.0.1:8080`, фронт на `http://localhost:5173`.
Обращения к `/api` фронт проксирует на бэкенд, поэтому в браузере нужен только
второй адрес. `Ctrl-C` останавливает оба процесса.

Порт бэкенда меняется переменной `AGENTBOX_PORT`, путь к базе — `AGENTBOX_DB`.
Параллельность вызовов LLM ограничивается `AGENTBOX_PROVIDER_CONCURRENCY` (4), а
локальных executor'ов — `AGENTBOX_EXECUTOR_CONCURRENCY` (2).

Слева — сессии и переходы в конфигурацию, библиотеку и матричный прогон.
Чат занимает свободное место; кнопка «Диагностика» открывает справа контекст,
память и профиль текущей сессии. Панель закрывается кнопкой или Escape,
последняя выбранная вкладка запоминается. На узком экране навигация и
диагностика открываются поверх содержимого.

Инструменты включаются рабочей папкой: раздел «инструменты» в конфигурации принимает путь и
режим подтверждения (`ask` — спрашивать перед записью и командами, `read-only` —
только чтение, `auto` — без вопросов). Без папки агент остаётся чат-агентом.
Для изолированной сессии выберите Docker и один раз соберите образ:

```bash
docker build -t agentbox-tools:latest backend/docker
```

Docker запускает каждый инструмент без сети; рабочая папка — единственный
доступный для записи mount. `AGENTBOX_DOCKER_IMAGE`,
`AGENTBOX_DOCKER_CPUS` (1), `AGENTBOX_DOCKER_MEMORY_MB` (512) и
`AGENTBOX_DOCKER_PIDS_LIMIT` (128) задают образ и лимиты контейнеров.

Левая колонка перечисляет сессии из базы: заголовок, модель, режим контекста,
расход и профиль пользователя. `×` удаляет сессию. Над чатом выбираются
пресет, модель и профиль пользователя; рядом — состояние памяти и кнопка
«Настроить». Для новой сессии исходными служат пресет и профиль со `★`.
До первого сообщения конфигурация остаётся черновиком без записи сессии в базе.

Профиль пользователя описывает человека, а не агента: язык, тон, объём, форму
ответа, код и ограничения. Вкладка «профиль» в диагностике показывает цену,
текст блока и кандидаты изменений. «Библиотека → Профили» позволяет создать,
дублировать, назначить по умолчанию, удалить и изменить профиль; ограничения
вводятся по одному на строку. Редактор показывает использующие его сессии:
сохранение меняет их следующие ответы. Правка создаёт новую
версию, и каждая строка расхода помнит хеш версии, с которой получен ответ.
Блок профиля получают ответ, подготовительные вызовы стратегии, планировщик и
роутер памяти; сводка его не получает. При конфликте формат ответа из
настроек агента важнее профиля, а профиль важнее памяти; прямая просьба в
текущем сообщении тоже важнее профиля, но язык самого вопроса просьбой не
считается.

Профиль учится из диалога только при включённом роутере памяти: на явную
просьбу о будущих ответах («впредь отвечай по-английски») роутер предлагает
новое значение поля. Поле и значение проверяются схемой профиля, чужое уходит в
отклонённые. Изменение всегда ждёт решения во вкладке «профиль» — «принять»
создаёт новую версию профиля, режима автозаписи у профиля нет. Без роутера
вкладка пишет, что автообучения нет.

Полоса задачи над лентой показывает этап, ожидаемое действие, полный план и
текущий шаг. «Новая задача» открывает планирование; ответ агента разбирается в
шаги и критерии, после чего человек утверждает именно эту версию плана и
инвариантов. Переход к проверке доступен только после всех шагов, завершение —
после `pass` и отдельного подтверждения; `force` эти проверки не обходит.
Заблокированная кнопка остаётся видна с причиной и следующим действием.
Пауза сохраняет этап, утверждение и вердикт; устаревший или поздний запрос не
двигает изменившуюся задачу. В планировании и на паузе инструментов нет; на
проверке доступны только чтение и поиск, пока нет отдельного безопасного
исполнителя команд.

Под ответом агента указаны модель, фактические входные, выходные и reasoning-
токены, стоимость и задержка. Маркеры в ленте отделяют сообщения вне окна и
часть, заменённую сводкой. Строка под композером показывает заполнение окна,
режим контекста и overflow; оттуда открывается точный состав следующего вызова.

«Конфигурация» содержит разделы модели, сэмплинга, ответа, рассуждения,
контекста, памяти, инструментов, задачи и судьи. Поиск охватывает обычные,
дополнительные и пока недоступные параметры; зависимые поля требуют включения
соответствующего режима. Описания доступны в подсказках. «Применить» сохраняет
изменённые настройки для следующего сообщения; «Отменить» возвращает
применённые значения. Переход между экранами сохраняет несохранённую форму;
смена сессии предлагает отменить её. Матричные сессии доступны только для чтения.

Ниже конфигурации агента находится отдельный редактор инвариантов текущей
сессии: архитектуры, технических решений, стека и бизнес-правил. «Применить»
проверяет хеш открытой версии, поэтому параллельная правка не перезаписывается
молча. Ветка копирует текущую версию, матричный прогон фиксирует её вместе с
котировкой. При активной задаче изменение требует явного возврата в
планирование и сбрасывает прежний план и вердикт. Подключение правил к ответам
обязательно: полный набор стоит в контексте перед профилем и памятью. Запрос,
подготовленный ответ и изменяющий инструмент проходят отдельную проверку;
конфликт даёт объяснимый отказ, а ошибка проверяющего останавливает действие.
Ответ появляется в ленте только после проверки. Версия, результат, причина и
стоимость видны во вкладке «контекст» и сохраняются в журнале сессии.

«Библиотека → Пресеты» управляет наборами настроек независимо от сессий:
создание из текущей конфигурации, дублирование, переименование, удаление,
редактирование и назначение по умолчанию. Правка сессии не обновляет пресет,
а правка пресета не изменяет уже открытые сессии.

«Библиотека → Эксперименты» сохраняет конфигурацию агента и профиль в этом
браузере. Начальные условия выбираются явно: чистая сессия с пустой памятью
или контрольная точка текущей сессии. Для точки диалог, задача и рабочая память
восстанавливаются на выбранном сообщении, долговременная память фиксируется
при сохранении эксперимента. Исходную сессию удалять нельзя. Каждый повтор
получает отдельную область долговременной памяти и независимую копию профиля;
изменение пресетов и профилей не подменяет сохранённые условия. Кнопка открытия
не отправляет сообщение и не запускает платный прогон. Готовые сценарии
помогают проверить персонализацию и продолжение задачи после паузы.

Реестр объединяет каталоги настроенных провайдеров; сейчас подключён Zen. В
конфигурации провайдер и модель выбираются из каталога, модели сгруппированы по
семейству и дополнены ценой за 1M входных/выходных токенов и размером
контекстного окна из `models.dev`. Модели дороже `AGENTBOX_MAX_MODEL_PRICE`
(5 $ за 1M входных токенов; `0` снимает ограничение) в списки не попадают, но
остаются видимы там, где уже выбраны, и сохраняют цену для оценки прогона.
Параметры сэмплинга, которых выбранная модель
не принимает, гаснут с объяснением и не уходят в запрос: например, ни одна
`gpt-*` модель Zen не принимает `temperature` и `top_p`. Вкладка «контекст»
показывает роль, профиль, слои памяти, состояние задачи, сводку, дословный
хвост и выпавшие сообщения
следующего вызова — у каждого блока своя оценка и доля вызова, — затем оценку
против факта, накопительный расход и рост по ходам.
`context.window_tokens`
задаёт искусственное окно вместо лимита `models.dev`, а `context.overflow`
выбирает обрезку старой истории (`drop`) или отказ до вызова (`fail`).
`context.mode=summary` вместо удаления периодически сворачивает старую
часть диалога дешёвой моделью: последние сообщения остаются дословными, а
вкладка показывает число покрытых сообщений и разворачиваемый текст последней
версии сводки. Summary-вызовы входят в общий расход отдельными строками.
Секция «память» добавляет к диалогу независимые слои. Рабочий слой хранит данные
текущей задачи и живёт в сессии, долговременный — сведения о человеке, решения
и знания —
живёт в пространстве памяти, общем для сессий. Блоки складываются в payload в
порядке «роль → профиль пользователя → долговременная → рабочая → задача →
сводка → последние сообщения» и не
зависят от выбранной стратегии контекста. Память обновляется отдельным дешёвым
вызовом после ответа: роутер сам называет слой и вид из словаря этого слоя —
`goal`, `constraint`, `step`, `artifact`, `blocker` у рабочего, `profile`
(во вкладке — «о человеке»), `decision`, `knowledge` у долговременного. Запись
в долговременный слой
управляется полем «запись»: `confirm` копит кандидатов до решения человека,
`auto` пишет сразу, `manual` оставляет слой только для ручной правки.
Включение рабочего слоя в существующем диалоге один раз извлекает память из
полной истории. Пространство задаётся полем «пространство памяти»: сессия
вступает в него при создании, поэтому новая сессия того же пространства
открывается уже со сведениями о человеке и решениями, а ветка делит пространство с
родителем и уносит с собой рабочий слой на точке развилки. У каждого слоя свой
бюджет блока в вызове: слой растёт с каждым ходом, а платится за него каждый
запрос, поэтому сверх бюджета в вызов уходят только самые свежие элементы —
остальные остаются в хранилище и в панели.

Вкладка «память» показывает три слоя карточками: краткосрочный — только для
чтения (режим, состав хвоста, число выпавших сообщений), рабочий и
долговременный — с местом хранения, версией, ценой блока в следующем вызове и
списком элементов. У элемента виден его маршрут (роутер, рука, перенос,
миграция) и `seq` источника; значение и вид правятся на месте, элемент можно
забыть или перенести в соседний слой под видом из его словаря. Кандидаты
роутера ждут решения отдельным списком — «принять» или «отклонить». Кнопка
«запомнить» на сообщении ленты пишет запись из него, явно называя слой и вид.
Опустевший слой сохраняет версию, но в вызов не уходит и ничего не стоит. Рядом
с ценой блока стоит бюджет слоя, а не попавшие в вызов элементы помечены «вне
вызова» и перечислены во вкладке «контекст».
У долговременной карточки видно пространство и число сессий в нём. При
завершении или отмене задачи рабочий слой закрывается: отмеченное уезжает в
долговременный слой, остальное уходит вместе с задачей.

Экран «матричный прогон с судьёй» использует выбранные пресеты как строки
матрицы и запускает в фоне N × M агентов. Отмеченные профили пользователя
добавляют вторую ось: конфигурация — пара «пресет · профиль», прогон
фиксирует версию профиля, и её последующая правка отчёт не меняет; Judge
профиль не получает. У каждой конфигурации есть модель и критерии Judge, проходной балл и действие при
провале: отдать ответ, повторить его один раз или вызвать запасную модель.
«Оценить стоимость» показывает верхнюю границу по живому каталогу с учётом
стратегии, Judge и восстановления; запуск возможен только второй кнопкой
подтверждения. Необязательный общий бюджет останавливает новые вызовы после
достигнутого фактического расхода. Дашборд показывает статусы агентов, расход
и очереди провайдера/executor'ов; итоговая таблица — долю прошедших, средний
балл, фактическую стоимость провайдера (не прайс-лист) и первый ответ,
строки сгруппированы по профилю. Завершённый отчёт можно
скачать в JSON с исходными данными или CSV с одной строкой на ячейку матрицы.

## Тесты

```bash
backend/.venv/bin/python -m pytest backend/tests   # бэкенд
npm --prefix frontend run build                    # типы и сборка фронта
```

Браузерная проверка настроек из корня репозитория:

```bash
npm --prefix agentbox/frontend run build
agentbox/backend/.venv/bin/python tools/check_settings_ui.py
```

Нужен Chrome (`CHROME_PATH` позволяет указать другой путь). Проверка запускает
временную базу, локальный сервер и тестовый LLM; рабочие данные и платный
провайдер не используются. Снимки экранов сохраняются в `/tmp/agentbox-settings-ui`.

## Раскладка

| Каталог | Что внутри |
|---|---|
| `backend/agentbox/core/` | ядро агента: спека, порты, память, ledger, пайплайн |
| `backend/agentbox/tools/` | инструменты и executor рабочей папки |
| `backend/agentbox/llm/` | реестр провайдеров, их клиенты, каталоги и capabilities |
| `backend/agentbox/store/` | схема SQLite, репозиторий |
| `backend/agentbox/api/` | FastAPI: маршруты и стриминг |
| `frontend/src/hooks/` | состояние диалога и загрузка настроек |
| `frontend/src/components/` | зоны интерфейса: сайдбар, чат, панель |
| `data/` | база SQLite, вне репозитория |
